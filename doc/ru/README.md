Локальное управление светильниками для бассейна **MiBoxer PW01 / PW02** (LoRa, 433 МГц) через шлюз **MiBoxer WL-433** — без облака, без голосового ассистента, прямо в вашей локальной сети.

Производитель: [MiBoxer (Futlight Optoelectronics)](https://miboxer.com/) — [WL-433](https://miboxer.com/product/lora-433mhz-gateway), [PW01](https://miboxer.com/product/27w-rgbcct-par56-led-pool-light-lora-433mhz)

## Отказ от ответственности

Это **неофициальный проект сообщества**. Он **не связан** с Shenzhen Futlight Optoelectronics Co., Ltd. (MiBoxer / Mi-Light) или Tuya и ими не поддерживается. «MiBoxer», «Mi-Light» и «Tuya» — товарные знаки соответствующих владельцев и используются только для описания совместимости устройств. Используйте адаптер на свой страх и риск.

## Принцип работы

Внутри WL-433 находится модуль Wi-Fi Tuya. В локальной сети шлюз является **одним** устройством Tuya: все связанные лампы управляются через это устройство, а шлюз передаёт команды лампам по LoRa (433 МГц). Адаптер напрямую общается со шлюзом по **протоколу Tuya LAN 3.3** (TCP-порт 6668, шифрование AES локальным ключом) на основе проверенной библиотеки [tuyapi](https://github.com/codetheweb/tuyapi) (её также использует ioBroker.tuya). Поддерживаются и версии протокола 3.1, 3.4 и 3.5 на случай, если обновление прошивки её изменит.

Лампы, зоны и сцены управляются собственными командами шлюза в специфичной для производителя **точке данных 101** — теми же командами, что отправляет приложение MiBoxer. Шлюз сообщает своё состояние тем же способом; кроме того, адаптер запрашивает его при подключении и при каждом обновлении состояния.

```text
ioBroker ──LAN: Tuya 3.3, TCP 6668──► WL-433 ──LoRa 433 MHz──► PW01 / PW02
```

**Руководство пользователя**, в котором каждый шаг объяснён для начинающих (установка, настройки, зоны, таймеры, примеры, устранение неполадок): [English](../Manual_miboxer-wl433.md) ([PDF](../Manual_miboxer-wl433.pdf)) · [Deutsch](../Handbuch_miboxer-wl433.md) ([PDF](../Handbuch_miboxer-wl433.pdf)).

Исходное исследование (анализ протокола, источники, план проверки, расшифрованная точка данных 101), на немецком: [Miboxer_WL-433_PW01_Protokollanalyse_lokale_Steuerung.md](../Miboxer_WL-433_PW01_Protokollanalyse_lokale_Steuerung.md) ([PDF](../Miboxer_WL-433_PW01_Protokollanalyse_lokale_Steuerung.pdf)). Инструкция по привязке ламп к шлюзу: [Anleitung_PW01_mit_WL-433_verbinden.pdf](../Anleitung_PW01_mit_WL-433_verbinden.pdf).

## Требования

1. Шлюз настроен в приложении MiBoxer, и лампы к нему привязаны.
2. **ID устройства и локальный ключ** шлюза. Производитель не поддерживает платформу разработчиков Tuya для WL-433, но приложение MiBoxer записывает оба значения в свой журнал отладки: на Android читайте журнал программой просмотра logcat, например *LogFox*, пока приложение запускается и управляет шлюзом. **Локальный ключ меняется при каждом повторном сопряжении шлюза** — тогда его нужно снова прочитать и ввести. Пошаговая инструкция для начинающих (на немецком, для Android, iPhone и iPad): [Anleitung_Geraete-ID_und_Local-Key_auslesen.md](../Anleitung_Geraete-ID_und_Local-Key_auslesen.md) ([PDF](../Anleitung_Geraete-ID_und_Local-Key_auslesen.pdf)).
3. Шлюз доступен из ioBroker (та же сеть). Рекомендуется резервирование DHCP; без указанного IP-адреса адаптер находит шлюз по его широковещательным UDP-сообщениям (порты 6666/6667).
4. **Устройства Tuya обычно принимают только одно локальное подключение.** В тесте приложение MiBoxer и адаптер были подключены одновременно; но если подключение снова и снова не удаётся, закройте приложение на телефонах в той же сети и не управляйте шлюзом одновременно другими локальными интеграциями (ioBroker.tuya, Home Assistant, tinytuya).

## Настройки

Настройки экземпляра содержат две вкладки: **Шлюз** (подключение и управление зонами) и **Таймеры** (см. [Таймеры](#таймеры)).

| Параметр | Описание |
| --- | --- |
| ID устройства | ID устройства Tuya шлюза WL-433 |
| Локальный ключ | 16-символьный локальный ключ Tuya (хранится в зашифрованном виде) |
| IP-адрес шлюза | Оставьте пустым, чтобы найти шлюз в локальной сети автоматически |
| Версия протокола Tuya | 3.3 для WL-433 (можно выбрать 3.1, 3.4 и 3.5) |
| Найти шлюз в локальной сети | Кнопка: находит шлюз по ID устройства и вписывает IP-адрес и версию протокола. Без ID устройства выводится список всех найденных устройств Tuya |
| Задержка переподключения | Секунды до повторной попытки потерянного или неудачного подключения (по умолчанию 30) |
| Интервал обновления состояния | Секунды между полными запросами состояния (по умолчанию 60, 0 = только обновления, присылаемые шлюзом) |
| Управление зонами | *Выбор зоны* (по умолчанию) или *отдельный канал для каждой зоны*, см. [Зоны](#зоны) |

## Зоны

Шлюз управляет до 8 зонами (как пульт FUT086). Каждая команда может идти в одну зону или во все зоны, но шлюз сообщает **только одно состояние для всех ламп: последнюю настройку, независимо от того, в какую зону она была отправлена**. Приложение MiBoxer тоже не показывает отдельное состояние по зонам. Параметр *Управление зонами* предлагает два варианта:

| Вариант | Состояния | Подходит для |
| --- | --- | --- |
| **Выбор зоны (по умолчанию)** | `light.*` показывает состояние шлюза. `light.zone` (0 = все зоны, 1–8) определяет, в какую зону отправляются команды `light.*`. | Большинство пользователей: каждое состояние показывает то, что сообщает шлюз |
| **Отдельный канал для каждой зоны** | `light.*` показывает состояние шлюза и отправляет команды во все зоны. Кроме того, `zones.zone1` … `zones.zone8` управляют каждой зоной отдельно. Канал зоны показывает последние значения, отправленные в эту зону и подтверждённые шлюзом; он остаётся пустым, пока в зону ничего не отправлено. | Скрипты и визуализации, которые обращаются к зонам напрямую |

При изменении параметра состояния другого варианта удаляются.

## Таймеры

Вкладка **Таймеры** в настройках экземпляра содержит до **50 таймеров**. Они работают локально в адаптере, в том числе без интернета, и умеют больше, чем таймеры приложения MiBoxer: солнечные события со смещением, случайное отклонение, сезон, зоны, цвета, сцены и выключение через заданное время. Добавьте таймер кнопкой **+**, откройте его, чтобы изменить, копируйте или удаляйте его кнопками записи. Изменения вступают в силу после сохранения настроек (экземпляр перезапускается).

| Поле | Описание |
| --- | --- |
| Активен | Отключает этот таймер, не удаляя его |
| Название | Отображается в журнале и в `timers.overview` |
| Триггер | *Время суток* или солнечное событие: рассвет, восход, золотой час (вечер), закат, сумерки, ночь |
| Время суток | Только для триггера *Время суток* |
| Смещение | Минуты (от −720 до 720), отрицательное значение = раньше — например, закат −15 |
| Случайное отклонение | До ± минут (0–120), заново выбирается случайно при каждом запуске — для имитации присутствия |
| Дни недели | Дни, в которые срабатывает таймер |
| Сезон с / по | `DD.MM.`, например с `01.05.` по `30.09.`; сезон, переходящий через Новый год (с `01.11.` по `28.02.`), тоже возможен; пусто = весь год |
| Зона | Все зоны или зона 1–8 |
| Действие | Включить, выключить, белый свет (цветовая температура 2700–6500 K), цвет, сцена M1–M9, только яркость |
| Яркость | 1–100 %, пусто = без изменений (кроме действия *Выключить*) |
| Выключить через | Минуты (0–1440), 0 = не выключать (кроме действия *Выключить*) |

- **Солнечные события** рассчитываются по местоположению из системных настроек ioBroker (широта и долгота) с помощью [suncalc](https://github.com/mourner/suncalc). Без местоположения такие таймеры игнорируются с предупреждением. В дни, когда события нет (полярные регионы), таймер не срабатывает.
- Таймер отправляет те же команды, что и состояния: при варианте управления зонами *выбор зоны* — в свою зону (`light.zone` не изменяется), при варианте *отдельный канал для каждой зоны* — через `zones.zone<n>` (все зоны: `light.*`). Шлюз подтверждает их, как и любую другую команду.
- Если в момент срабатывания таймера шлюз не подключён, этот запуск пропускается (предупреждение в журнале) — позже он не повторяется.
- Таймеры с неполными настройками игнорируются; причину указывают журнал и `timers.overview`.
- Время — это местное время системы ioBroker; переход на летнее время учитывается.
- **Таймеры приложения MiBoxer** хранятся и выполняются в облаке Tuya (они только включают или выключают все зоны через точку данных 20 и требуют интернета). Адаптер не может их прочитать или изменить, но видит их действие в состоянии. Оба вида таймеров можно использовать одновременно.

## Состояния

| State | Описание |
| --- | --- |
| `info.connection` | Подключение к шлюзу |
| `info.ip` | Используемый IP-адрес шлюза |
| `light.on` | Вкл. / выкл. |
| `light.mode` | `white`, `colour` или `scene` — запись переключает режим (цветной режим с последним оттенком, режим сцены с последней сценой) |
| `light.brightness` | Яркость 1–100 % текущего режима. 0 выключает, значение больше 0 включает |
| `light.colorTemperature` | Цветовая температура 2700–6500 K с шагом 100 K (переключает в белый режим) |
| `light.color` | Цвет в формате `#rrggbb` при полной яркости (переключает в цветной режим). Запись задаёт оттенок и насыщенность, яркость значения RGB игнорируется — используйте `light.brightness` |
| `light.hue` | Оттенок 0–360° (переключает в цветной режим) |
| `light.saturation` | Насыщенность 0–100 % (переключает в цветной режим) |
| `light.scene` | Сцена 1–9 (M1–M9 в приложении), 0 = без сцены. Запись 1–9 запускает сцену |
| `light.speedUp` / `light.speedDown` | Кнопки S+ / S- приложения: сцена быстрее / медленнее. Шлюз не сообщает скорость |
| `light.countdown` | Секунды до переключения ламп шлюзом (0 = выкл., стандартная точка данных 26) |
| `light.zone` | Только при выборе зоны: зона команд `light.*`, 0 = все зоны, 1–8 |
| `zones.zone<n>.*` | Только при отдельном канале для каждой зоны: `on`, `mode`, `brightness`, `colorTemperature`, `color`, `hue`, `saturation`, `scene`, `speedUp`, `speedDown` для зоны n |
| `dp101.raw` | Последний кадр точки данных 101 в Base64 — запись отправляет значение без изменений |
| `dp101.hex` | Последний кадр точки данных 101 в шестнадцатеричных байтах — запись отправляет кадр, контрольная сумма добавляется или исправляется автоматически |
| `dp101.checksumValid` | Контрольная сумма последнего кадра верна |
| `dp101.history` | JSON-список последних 50 кадров (`rx` = принят, `tx` = отправлен) с отметкой времени; повторяющиеся одинаковые ответы о состоянии не добавляются |
| `raw.dp<n>` | Любая другая точка данных, о которой сообщает шлюз, создаётся автоматически (доступна для записи) |
| `settings.dmxAddress` | Начальный адрес 1–512 входа DMX512 шлюза — начиная с него шлюз использует 5 каналов: красный, зелёный, синий, холодный белый, тёплый белый (меню *DMX* в приложении). Запись отправляет его в зону из `light.zone` (выбор зоны) или во все зоны; шлюз его подтверждает |
| `timers.active` | `false` приостанавливает все таймеры (например, на время отпуска или из скрипта), `true` снова запускает их |
| `timers.nextRun` | Следующий запуск таймера с названием таймера (`paused (…)`, пока `timers.active` равно `false`) |
| `timers.lastRun` | Последний запуск таймера с названием и действием |
| `timers.overview` | JSON-список всех таймеров: расписание, действие, следующий запуск, причина, если таймер игнорируется |

Значения, которым нужен определённый режим или включённые лампы, адаптер отправляет так же, как приложение MiBoxer: например, цветовая температура в цветном режиме сначала переключает в белый режим, а яркость при выключенных лампах сначала их включает. Быстрые изменения (например, с ползунка) объединяются, отправляется только последнее значение. Команды принимаются только при подключённом шлюзе. Команда считается выполненной, когда следующее состояние шлюза показывает её значения (примерно через 2,5 с); до этого состояние не подтверждено.

## Точка данных 101 — протокол

WL-433 передаёт лампы, зоны и сцены в специфичной для производителя точке данных 101: 12-байтовые кадры в кодировке Base64, последний байт — 8-битная сумма байтов 0–10. Формат был расшифрован 22.09.2026 по кадрам состояния реального шлюза и командам, которые приложение MiBoxer записывает в свой журнал Android:

| Кадр | Bytes (hex) | Значение |
| --- | --- | --- |
| Команда (приложение / адаптер → шлюз) | `41 00 00 0B cc vv vv vv vv zz 80 ss` | `cc` команда: `01` оттенок 0–255 (значение в байтах 5–8, переключает в цветной режим), `02` яркость 1–100 %, `03` цветовая температура 0–38 (2700 K + 100 K за шаг), `04` насыщенность 0–100 %, `05` сцена 1–9, `06` клавиша (`01` вкл., `02` выкл., `03` S-, `04` S+, `06` белый режим); `zz` зона: `00` все, `01`–`08` |
| Запрос состояния | `43 00 00 80 00 00 00 00 00 80 80 C3` | шлюз отвечает кадром состояния `44` |
| Состояние (шлюз → приложение) | `42` / `44` `00 00 00 mm hh tt bb ss 0B dd xx` | `42` сообщение об изменении (примерно через 2,5 с после последнего изменения), `44` ответ на запрос; `mm` режим: `00` выкл., `01` цвет, `02` белый, `03`–`0B` сцена 1–9; `hh` оттенок, `tt` шаг цветовой температуры, `bb` яркость, `ss` насыщенность (0 в белом режиме), `dd` младший байт начального адреса DMX. Зона не входит в состояние |
| Начальный адрес DMX | `49 00 00 0B 02 aa aa 00 00 zz 80 ss` | `aa aa` адрес 1–512 (старший байт, младший байт), `zz` зона; ответ `49 00 00 0B 02 01 tt bb ss aa aa xx` |

Клавиша `06 05` тоже выключает лампы (повторное нажатие оставляет их выключенными, это не переключатель); чем она отличается от `06 02`, пока неизвестно, адаптер её не использует. Стандартные точки данных 20–23 шлюз выводит из этих команд; адаптер использует только точку данных 20 (вкл./выкл., приходит раньше состояния), а во всём остальном следует состоянию из точки данных 101. Запись точки данных цвета Tuya 24 не меняет цвет ламп — приложение MiBoxer её тоже не использует.

Прямой доступ для собственных экспериментов: `dp101.hex` принимает 11 байтов (контрольная сумма добавляется), например `43 00 00 80 00 00 00 00 00 80 80` запрашивает состояние.

## Ограничения

- Шлюз сообщает одно состояние для всех ламп (последнюю настройку), а не состояние каждой зоны — см. [Зоны](#зоны).
- Скорость сцены (S+ / S-) шлюз не сообщает.
- Нельзя увидеть, действительно ли лампа получила команду по радио: состояние поступает от шлюза.
- Шлюз по-прежнему сообщает своё состояние в облако Tuya. Полная блокировка доступа в интернет может сделать его ненадёжным. Таймерам приложения MiBoxer нужно облако, таймерам адаптера — нет.

## Журналирование и поиск неисправностей

Адаптер ведёт журнал по фиксированной схеме, чтобы журнал в любой момент был полезен для поиска ошибок:

| Уровень | Что записывается |
| --- | --- |
| error | Ошибки конфигурации, из-за которых адаптер не может работать (нет ID устройства, локальный ключ не из 16 символов) |
| warn | Проблемы, требующие ваших действий, — сообщаются один раз, а затем только на уровне debug, пока не будут устранены: шлюз отклоняет подключения, данные не удаётся расшифровать (неверный локальный ключ), команды не подтверждены шлюзом, запросы состояния без ответа, неожиданные значения точек данных или кадры состояния, таймеры с неполными настройками или без местоположения для солнечных событий, таймеры, которые не смогли переключить лампы, начальный адрес DMX, не подтверждённый шлюзом |
| info | Ключевые события: сводка конфигурации при запуске, шлюз найден, подключён, подключение потеряно, подключение снова стабильно, объекты другого варианта зон удалены, число активных таймеров, таймеры приостановлены или снова активны |
| debug | Каждый шаг с входными данными, решениями и длительностью: изменение состояния → преобразование в кадры точки данных 101 (с причиной дополнительных кадров, например «сначала включить») → очередь команд → отправка → подтверждение состоянием (или какое значение ещё отсутствует), каждая полученная точка данных и состояние и обновлённые состояния, запросы состояния, поиск, каждый таймер с расписанием, следующим запуском (солнечное событие, смещение, случайное отклонение) и выполнением. Команды (`#12`) и попытки подключения (`Attempt #3`) пронумерованы, поэтому все строки одной команды можно проследить |
| silly | Дополнительно трассировка протокола библиотеки tuyapi (пакеты, ping/pong) с меткой `[tuyapi]` |

Каждое сообщение начинается с метки: `[cfg]` конфигурация, `[conn]` подключение, `[rx]` шлюз → состояния, `[cmd]` состояния → команды, `[queue]` очередь команд, `[poll]` обновление и запрос состояния, `[disc]` поиск, `[dp101]` необработанные кадры, `[timer]` таймеры, `[unload]` завершение, `[tuyapi]` трассировка библиотеки. Локальный ключ и ключи сеанса никогда не появляются в журнале — сводка конфигурации показывает только длину ключа.

Изменение уровня: Admin → **Экземпляры** → режим эксперта → уровень журнала `miboxer-wl433.0` → `debug` (или `silly` для трассировки протокола; затем перезапустите экземпляр). Прикладывайте журнал debug и содержимое `dp101.history`, когда сообщаете о проблеме.
