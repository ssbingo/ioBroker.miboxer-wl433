Локальное управление светильниками для бассейна **MiBoxer PW01 / PW02** (LoRa, 433 МГц) через шлюз **MiBoxer WL-433** — без облака, без голосового ассистента, прямо в вашей локальной сети.

Производитель: [MiBoxer (Futlight Optoelectronics)](https://miboxer.com/) — [WL-433](https://miboxer.com/product/lora-433mhz-gateway), [PW01](https://miboxer.com/product/27w-rgbcct-par56-led-pool-light-lora-433mhz)

## Принцип работы

Внутри WL-433 находится Wi-Fi-модуль Tuya. В локальной сети шлюз является **одним** устройством Tuya — все привязанные светильники управляются через него, а шлюз передаёт команды светильникам по LoRa (433 МГц). Адаптер напрямую общается со шлюзом по **протоколу Tuya LAN 3.3** (TCP-порт 6668, шифрование AES локальным ключом) с помощью проверенной библиотеки [tuyapi](https://github.com/codetheweb/tuyapi) (её использует и ioBroker.tuya). Версии протокола 3.1, 3.4 и 3.5 также поддерживаются на случай обновления прошивки.

```text
ioBroker ──LAN: Tuya 3.3, TCP 6668──► WL-433 ──LoRa 433 MHz──► PW01 / PW02
```

Исследование (анализ протокола, источники, план проверки) на немецком языке: [Miboxer_WL-433_PW01_Protokollanalyse_lokale_Steuerung.md](../Miboxer_WL-433_PW01_Protokollanalyse_lokale_Steuerung.md) ([PDF](../Miboxer_WL-433_PW01_Protokollanalyse_lokale_Steuerung.pdf)). Инструкция по привязке светильников к шлюзу: [Anleitung_PW01_mit_WL-433_verbinden.pdf](../Anleitung_PW01_mit_WL-433_verbinden.pdf).

| MiBoxer PW01 (27 W RGB+CCT PAR56) | Светильник, привязанный к шлюзу | Целевое устройство |

## Требования

1. Шлюз настроен в приложении MiBoxer, светильники к нему привязаны.
2. **ID устройства и локальный ключ** шлюза. Производитель не поддерживает платформу разработчиков Tuya для WL-433, но приложение MiBoxer записывает оба значения в отладочный журнал: на Android читайте журнал программой просмотра logcat, например *LogFox*, пока приложение запускается и управляет шлюзом. **Локальный ключ меняется при каждом повторном сопряжении шлюза** — тогда его нужно получить и ввести заново.
3. Шлюз доступен из ioBroker (та же сеть). Рекомендуется резервирование адреса в DHCP; без указанного IP-адреса адаптер находит шлюз по его UDP-рассылкам (порты 6666/6667).
4. **Устройства Tuya допускают только одно локальное соединение.** Закройте приложение MiBoxer на телефонах в той же сети и не управляйте шлюзом одновременно через другие локальные интеграции (ioBroker.tuya, Home Assistant, tinytuya).

## Настройки

| Параметр | Описание |
| --- | --- |
| ID устройства | Tuya ID шлюза WL-433 |
| Локальный ключ | 16-символьный локальный ключ Tuya (хранится в зашифрованном виде) |
| IP-адрес шлюза | Оставьте пустым для автоматического поиска шлюза в локальной сети |
| Версия протокола Tuya | 3.3 для WL-433 (можно выбрать 3.1, 3.4 и 3.5) |
| Найти шлюз в локальной сети | Кнопка: находит шлюз по ID устройства и вносит IP-адрес и версию протокола. Без ID выводит все найденные устройства Tuya |
| Задержка переподключения | Секунды до повторной попытки соединения (по умолчанию 30) |
| Интервал обновления статуса | Секунды между полными запросами статуса (по умолчанию 60, 0 = только обновления от шлюза) |

## Состояния

| State | Tuya DP | Описание |
| --- | --- | --- |
| `info.connection` | – | Соединение со шлюзом |
| `info.ip` | – | Используемый IP-адрес шлюза |
| `light.on` | 20 | Включение/выключение всех светильников |
| `light.mode` | 21 | `white`, `colour`, `scene`, `music` |
| `light.brightness` | 22 / 24 | Яркость 0–100 %. В цветовом режиме меняется яркость цвета (DP 24), иначе яркость белого (DP 22). 0 выключает, значение больше 0 включает |
| `light.colorTemperature` | 23 | Цветовая температура 2700–6500 K (переключает в белый режим) |
| `light.color` | 24 | Цвет в формате `#rrggbb` (переключает в цветовой режим) |
| `light.countdown` | 26 | Секунды до переключения светильников шлюзом (0 = выкл.) |
| `dp101.raw` | 101 | Последний кадр DP 101 в Base64 — запись отправляет значение без изменений |
| `dp101.hex` | 101 | Последний кадр DP 101 в виде hex-байтов — запись отправляет кадр, контрольная сумма добавляется или исправляется автоматически |
| `dp101.checksumValid` | 101 | Контрольная сумма последнего кадра верна |
| `dp101.history` | 101 | JSON-список последних 50 кадров (`rx` = получен, `tx` = отправлен) с отметкой времени |
| `raw.dp<n>` | n | Любая другая точка данных шлюза создаётся автоматически (доступна для записи) |

Быстрые изменения (например, от ползунка) объединяются в одну команду. Команды принимаются только при подключённом шлюзе.

## Точка данных 101 — зоны и сцены

WL-433 передаёт команды зон и сцен в специфичной для производителя точке данных 101: 12-байтовые двоичные кадры в Base64, последний байт — 8-битная сумма байтов 0–10. Значение остальных байтов **пока не расшифровано**. До тех пор адаптер предоставляет прямой доступ:

- полученные кадры отображаются в `dp101.raw` / `dp101.hex` и записываются в `dp101.history`,
- кадры можно отправлять через `dp101.hex` — достаточно 11 байтов, контрольная сумма добавляется автоматически, например `43 00 00 80 00 00 00 00 00 80 80`

**Нужна помощь:** выполняйте в приложении MiBoxer по одному действию (для каждой зоны: вкл., выкл., цвет, сцена 1–9) и записывайте кадры из `dp101.history`. При достаточном количестве записей кадры можно расшифровать и добавить отдельные состояния для зон и сцен. Порядок действий описан в главе 6 анализа протокола.

## Ограничения

- Стандартные точки данных 20–26 действуют на все светильники шлюза (возможно, только на выбранную в приложении зону). Отдельные зоны и сцены появятся после расшифровки точки данных 101.
- Шлюз продолжает сообщать своё состояние в облако Tuya. Полная блокировка доступа в интернет может сделать его работу нестабильной.
- Первая версия протестирована с симуляцией шлюза (протокол Tuya 3.3). Отзывы о работе с реальным оборудованием очень приветствуются.
