Локальне керування світильниками для басейну **MiBoxer PW01 / PW02** (LoRa, 433 МГц) через шлюз **MiBoxer WL-433** — без хмари, без голосового асистента, безпосередньо у вашій локальній мережі.

Виробник: [MiBoxer (Futlight Optoelectronics)](https://miboxer.com/) — [WL-433](https://miboxer.com/product/lora-433mhz-gateway), [PW01](https://miboxer.com/product/27w-rgbcct-par56-led-pool-light-lora-433mhz)

## Принцип роботи

Усередині WL-433 є Wi-Fi-модуль Tuya. У локальній мережі шлюз є **одним** пристроєм Tuya — усі прив'язані світильники керуються через нього, а шлюз передає команди світильникам через LoRa (433 МГц). Адаптер безпосередньо спілкується зі шлюзом за **протоколом Tuya LAN 3.3** (TCP-порт 6668, шифрування AES локальним ключем) на основі перевіреної бібліотеки [tuyapi](https://github.com/codetheweb/tuyapi) (її використовує й ioBroker.tuya). Версії протоколу 3.1, 3.4 і 3.5 також підтримуються на випадок оновлення прошивки.

```text
ioBroker ──LAN: Tuya 3.3, TCP 6668──► WL-433 ──LoRa 433 MHz──► PW01 / PW02
```

Дослідження (аналіз протоколу, джерела, план перевірки) доступне німецькою: [Miboxer_WL-433_PW01_Protokollanalyse_lokale_Steuerung.md](../Miboxer_WL-433_PW01_Protokollanalyse_lokale_Steuerung.md) ([PDF](../Miboxer_WL-433_PW01_Protokollanalyse_lokale_Steuerung.pdf)). Інструкція з прив'язування світильників до шлюзу: [Anleitung_PW01_mit_WL-433_verbinden.pdf](../Anleitung_PW01_mit_WL-433_verbinden.pdf).

## Підтримуване обладнання

| Пристрій | Роль | Статус |
| --- | --- | --- |
| MiBoxer WL-433 | Обов'язковий, адаптер підключається до нього | Протокол Tuya 3.3 підтверджено користувачем з ідентичним обладнанням |
| MiBoxer PW01 (27 W RGB+CCT PAR56) | Світильник, прив'язаний до шлюзу | Цільовий пристрій |
| MiBoxer PW02 (18 W RGB+CCT PAR56) | Світильник, прив'язаний до шлюзу | Та сама родина продуктів, має працювати |
| MiBoxer UW01, UW02, UW03, RD-9L | Світильник, прив'язаний до шлюзу | Не перевірено |

## Вимоги

1. Шлюз налаштовано в застосунку MiBoxer, світильники до нього прив'язані.
2. **ID пристрою та локальний ключ** шлюзу. Виробник не підтримує платформу розробників Tuya для WL-433, але застосунок MiBoxer записує обидва значення у свій журнал налагодження: на Android читайте журнал переглядачем logcat, наприклад *LogFox*, поки застосунок запускається й керує шлюзом. **Локальний ключ змінюється під час кожного повторного сполучення шлюзу** — тоді його потрібно отримати й ввести знову.
3. Шлюз доступний з ioBroker (та сама мережа). Рекомендовано резервування адреси в DHCP; без указаної IP-адреси адаптер знаходить шлюз за його UDP-розсиланнями (порти 6666/6667).
4. **Пристрої Tuya приймають лише одне локальне з'єднання.** Закрийте застосунок MiBoxer на телефонах у тій самій мережі та не керуйте шлюзом одночасно іншими локальними інтеграціями (ioBroker.tuya, Home Assistant, tinytuya).

| ID пристрою | Tuya ID шлюзу WL-433 |
| Локальний ключ | 16-символьний локальний ключ Tuya (зберігається зашифрованим) |
| IP-адреса шлюзу | Залиште порожнім для автоматичного пошуку шлюзу в локальній мережі |
| Версія протоколу Tuya | 3.3 для WL-433 (можна вибрати 3.1, 3.4 і 3.5) |
| Знайти шлюз у локальній мережі | Кнопка: знаходить шлюз за ID пристрою та вносить IP-адресу й версію протоколу. Без ID виводить усі знайдені пристрої Tuya |
| Затримка перепідключення | Секунди до повторної спроби з'єднання (типово 30) |
| Інтервал оновлення стану | Секунди між повними запитами стану (типово 60, 0 = лише оновлення від шлюзу) |

## Стани

| State | Tuya DP | Опис |
| --- | --- | --- |
| `info.connection` | – | З'єднання зі шлюзом |
| `info.ip` | – | Використана IP-адреса шлюзу |
| `light.on` | 20 | Увімкнення/вимкнення всіх світильників |
| `light.mode` | 21 | `white`, `colour`, `scene`, `music` |
| `light.brightness` | 22 / 24 | Яскравість 0–100 %. У кольоровому режимі змінюється яскравість кольору (DP 24), інакше яскравість білого (DP 22). 0 вимикає, значення понад 0 вмикає |
| `light.colorTemperature` | 23 | Колірна температура 2700–6500 K (перемикає в білий режим) |
| `light.color` | 24 | Колір у форматі `#rrggbb` (перемикає в кольоровий режим) |
| `light.countdown` | 26 | Секунди до перемикання світильників шлюзом (0 = вимк.) |
| `dp101.raw` | 101 | Останній кадр DP 101 у Base64 — запис надсилає значення без змін |
| `dp101.hex` | 101 | Останній кадр DP 101 як hex-байти — запис надсилає кадр, контрольна сума додається або виправляється автоматично |
| `dp101.checksumValid` | 101 | Контрольна сума останнього кадру правильна |
| `dp101.history` | 101 | JSON-список останніх 50 кадрів (`rx` = отримано, `tx` = надіслано) з позначкою часу |
| `raw.dp<n>` | n | Кожна інша точка даних шлюзу створюється автоматично (доступна для запису) |

Швидкі зміни (наприклад, від повзунка) об'єднуються в одну команду. Команди приймаються лише тоді, коли шлюз підключено.

## Точка даних 101 — зони та сцени

WL-433 передає команди зон і сцен у специфічній для виробника точці даних 101: 12-байтові двійкові кадри в Base64, останній байт — 8-бітна сума байтів 0–10. Значення інших байтів **ще не розшифровано**. До того часу адаптер надає прямий доступ:

- отримані кадри відображаються в `dp101.raw` / `dp101.hex` і записуються в `dp101.history`,
- кадри можна надсилати через `dp101.hex` — достатньо 11 байтів, контрольна сума додається автоматично, наприклад `43 00 00 80 00 00 00 00 00 80 80`

**Потрібна допомога:** виконуйте в застосунку MiBoxer по одній дії (для кожної зони: увімк., вимк., колір, сцена 1–9) і записуйте кадри з `dp101.history`. За достатньої кількості записів кадри можна буде розшифрувати й додати окремі стани для зон і сцен. Порядок дій описано в розділі 6 аналізу протоколу.

## Обмеження

- Стандартні точки даних 20–26 діють на всі світильники шлюзу (можливо, лише на вибрану в застосунку зону). Окремі зони та сцени з'являться після розшифрування точки даних 101.
- Шлюз і далі повідомляє свій стан у хмару Tuya. Повне блокування доступу до інтернету може зробити його роботу нестабільною.
- Першу версію протестовано із симуляцією шлюзу (протокол Tuya 3.3). Відгуки щодо роботи з реальним обладнанням дуже вітаються.
