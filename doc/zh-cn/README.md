## 工作原理

WL-433 内置一个涂鸦 Wi-Fi 模块。在局域网中，网关是**一个**涂鸦设备：所有关联的灯都通过这个设备控制，网关通过 LoRa（433 MHz）把命令转发给灯。适配器基于成熟的 [tuyapi](https://github.com/codetheweb/tuyapi) 库（ioBroker.tuya 也在使用），直接用**涂鸦局域网协议 3.3**（TCP 端口 6668，使用本地密钥进行 AES 加密）与网关通信。协议版本 3.1、3.4 和 3.5 同样受支持，以防固件更新改变协议版本。

灯、区域和场景通过网关在厂商专用**数据点 101** 中的自有命令进行控制——与 MiBoxer 应用发送的命令相同。网关以同样的方式报告状态；此外，适配器在连接时以及每次状态刷新时都会主动查询状态。

```text
ioBroker ──LAN: Tuya 3.3, TCP 6668──► WL-433 ──LoRa 433 MHz──► PW01 / PW02
```

## 前提条件

1. 网关已在 MiBoxer 应用中设置，并且灯已与其关联。
2. 网关的**设备 ID 和本地密钥**。厂商不支持在涂鸦开发者平台上使用 WL-433，但 MiBoxer 应用会把这两个值写入其调试日志：在 Android 上，在应用启动并控制网关时，用 *LogFox* 等 logcat 查看器读取日志。**每次重新配对网关时本地密钥都会改变**——之后必须重新读取并输入。面向初学者的分步指南（德语，适用于 Android、iPhone 和 iPad）：[Anleitung_Geraete-ID_und_Local-Key_auslesen.md](../Anleitung_Geraete-ID_und_Local-Key_auslesen.md)（[PDF](../Anleitung_Geraete-ID_und_Local-Key_auslesen.pdf)）。
3. ioBroker 可以访问网关（同一网络）。建议为网关设置 DHCP 保留；若未配置 IP 地址，适配器会通过网关的 UDP 广播（端口 6666/6667）找到它。
4. **涂鸦设备通常只接受一个本地连接。** 在一次测试中 MiBoxer 应用和适配器同时保持连接；但如果连接反复失败，请关闭同一网络中手机上的应用，并且不要同时用其他本地集成（ioBroker.tuya、Home Assistant、tinytuya）控制网关。

## 配置

实例设置有两个选项卡：**网关**（连接和区域控制）和**定时器**（见[定时器](#定时器)）。

| 设置 | 说明 |
| --- | --- |
| 设备 ID | WL-433 网关的涂鸦设备 ID |
| 本地密钥 | 16 个字符的涂鸦本地密钥（加密存储） |
| 网关 IP 地址 | 留空则在局域网中自动查找网关 |
| 涂鸦协议版本 | WL-433 使用 3.3（可选 3.1、3.4 和 3.5） |
| 在局域网中搜索网关 | 按钮：根据设备 ID 查找网关并填入 IP 地址和协议版本。未填写设备 ID 时列出所有找到的涂鸦设备 |
| 重新连接等待时间 | 连接丢失或失败后重试前的秒数（默认 30） |
| 状态刷新间隔 | 两次完整状态查询之间的秒数（默认 60，0 = 仅使用网关主动推送的更新） |
| 区域控制 | *区域选择*（默认）或*每个区域一个通道*，见[区域](#区域) |

## 区域

网关最多控制 8 个区域（与 FUT086 遥控器相同）。每条命令可以发送到一个区域或所有区域，但网关**只为所有灯报告一个状态：最后一次设置，无论它发送到哪个区域**。MiBoxer 应用也不会为每个区域显示单独的状态。*区域控制*设置提供两种方式：

| 方式 | 状态 | 适用于 |
| --- | --- | --- |
| **区域选择（默认）** | `light.*` 显示网关的状态。`light.zone`（0 = 所有区域，1–8）选择 `light.*` 的命令发送到哪个区域。 | 大多数用户：每个状态都显示网关报告的内容 |
| **每个区域一个通道** | `light.*` 显示网关的状态并向所有区域发送命令。此外，`zones.zone1` … `zones.zone8` 分别控制每个区域。区域通道显示最后发送到该区域并经网关确认的值；在向该区域发送任何内容之前，它保持为空。 | 直接控制各区域的脚本和可视化界面 |

更改此设置后，另一种方式的状态将被删除。

## 定时器

实例设置中的**定时器**选项卡最多可容纳 **50 个定时器**。它们在适配器中本地运行，没有互联网也能工作，而且功能比 MiBoxer 应用的定时器更多：带偏移的太阳事件、随机偏差、季节、区域、颜色、场景以及在一段时间后关闭。用 **+** 添加定时器，打开条目即可修改，用条目上的按钮复制或删除。保存设置后更改生效（实例会重新启动）。

| 字段 | 说明 |
| --- | --- |
| 启用 | 停用此定时器而不删除它 |
| 名称 | 显示在日志和 `timers.overview` 中 |
| 触发 | *时间点*或太阳事件：黎明、日出、黄金时刻（傍晚）、日落、黄昏、夜晚 |
| 时间点 | 仅用于触发方式*时间点* |
| 偏移 | 分钟（−720 至 720），负数 = 提前——例如日落 −15 |
| 随机偏差 | 最多 ± 分钟（0–120），每次运行时重新随机抽取——用于模拟有人在家 |
| 星期 | 定时器运行的日子 |
| 季节开始 / 结束 | `DD.MM.`，例如 `01.05.` 至 `30.09.`；跨年的季节（`01.11.` 至 `28.02.`）同样可用；留空 = 全年 |
| 区域 | 所有区域或区域 1–8 |
| 动作 | 打开、关闭、白光（色温 2700–6500 K）、颜色、场景 M1–M9、仅亮度 |
| 亮度 | 1–100 %，留空 = 不变（不适用于*关闭*） |
| 之后关闭 | 分钟（0–1440），0 = 不关闭（不适用于*关闭*） |

- **太阳事件**根据 ioBroker 系统设置中的位置（纬度和经度）用 [suncalc](https://github.com/mourner/suncalc) 计算。没有位置时，这些定时器会被忽略并记录警告。在没有该事件的日子（极地地区），定时器不会运行。
- 定时器发送的命令与状态相同：在区域模式*区域选择*下发送到其区域（`light.zone` 不会改变），在*每个区域一个通道*模式下通过 `zones.zone<n>` 发送（所有区域：`light.*`）。网关会像确认每条命令一样确认它们。
- 如果定时器到期时网关未连接，则跳过本次运行（日志中有警告）——之后不会补做。
- 设置不完整的定时器会被忽略；日志和 `timers.overview` 会说明原因。
- 时间为 ioBroker 系统的本地时间；已考虑夏令时。
- **MiBoxer 应用的定时器**存储并执行于涂鸦云中（它们只通过数据点 20 打开或关闭所有区域，并且需要互联网）。适配器无法读取或更改它们，但能在状态中看到它们的效果。两种定时器可以同时使用。

## 状态

| State | 说明 |
| --- | --- |
| `info.connection` | 与网关的连接 |
| `info.ip` | 网关使用的 IP 地址 |
| `light.on` | 开 / 关 |
| `light.mode` | `white`、`colour` 或 `scene`——写入会切换模式（彩色模式使用上次的色调，场景模式使用上次的场景） |
| `light.brightness` | 当前模式的亮度 1–100 %。0 关闭，大于 0 的值开启 |
| `light.colorTemperature` | 色温 2700–6500 K，步长 100 K（切换到白光模式） |
| `light.color` | 颜色，格式为全亮度下的 `#rrggbb`（切换到彩色模式）。写入会设置色调和饱和度，RGB 值的亮度将被忽略——请使用 `light.brightness` |
| `light.hue` | 色调 0–360°（切换到彩色模式） |
| `light.saturation` | 饱和度 0–100 %（切换到彩色模式） |
| `light.scene` | 场景 1–9（应用中的 M1–M9），0 = 无场景。写入 1–9 启动场景 |
| `light.speedUp` / `light.speedDown` | 应用中的 S+ / S- 按钮：场景变快 / 变慢。网关不报告速度 |
| `light.countdown` | 网关切换灯之前的秒数（0 = 关闭，标准数据点 26） |
| `light.zone` | 仅限区域选择：`light.*` 命令的区域，0 = 所有区域，1–8 |
| `zones.zone<n>.*` | 仅限每个区域一个通道：区域 n 的 `on`、`mode`、`brightness`、`colorTemperature`、`color`、`hue`、`saturation`、`scene`、`speedUp`、`speedDown` |
| `dp101.raw` | 数据点 101 的最后一帧（Base64）——写入会原样发送该值 |
| `dp101.hex` | 数据点 101 的最后一帧（十六进制字节）——写入会发送该帧，校验和会自动添加或更正 |
| `dp101.checksumValid` | 最后一帧的校验和有效 |
| `dp101.history` | 最近 50 帧的 JSON 列表（`rx` = 接收，`tx` = 发送），带时间戳；重复的相同状态应答不会加入 |
| `raw.dp<n>` | 网关报告的其他任何数据点都会自动创建（可写） |
| `settings.dmxAddress` | 网关 DMX512 输入的起始地址 1–512——网关从该地址起使用 5 个通道：红、绿、蓝、冷白、暖白（应用中的 *DMX* 菜单）。写入会将其发送到 `light.zone` 的区域（区域选择）或所有区域；网关会确认 |
| `timers.active` | `false` 暂停所有定时器（例如在假期期间或由脚本控制），`true` 重新启用它们 |
| `timers.nextRun` | 下一次定时器运行及定时器名称（`timers.active` 为 `false` 时显示 `paused (…)`） |
| `timers.lastRun` | 上一次定时器运行及其名称和动作 |
| `timers.overview` | 所有定时器的 JSON 列表：计划、动作、下次运行、定时器被忽略时的原因 |

需要特定模式或灯处于开启状态的值，适配器会像 MiBoxer 应用一样发送：例如在彩色模式下设置色温会先切换到白光模式，灯关闭时设置亮度会先开灯。快速变化（例如来自滑块）会被合并，只发送最后一个值。仅在网关连接时才接受命令。当网关的下一个状态显示命令的值时（约 2.5 秒后），命令被视为已执行；在此之前状态不会被确认。

## 数据点 101——协议

WL-433 通过厂商专用数据点 101 传输灯、区域和场景：12 字节帧，Base64 编码，最后一个字节是字节 0–10 的 8 位和。该格式于 2026-09-22 根据真实网关的状态帧以及 MiBoxer 应用写入其 Android 日志的命令解码：

| 帧 | Bytes (hex) | 含义 |
| --- | --- | --- |
| 命令（应用 / 适配器 → 网关） | `41 00 00 0B cc vv vv vv vv zz 80 ss` | `cc` 命令：`01` 色调 0–255（值位于字节 5–8，切换到彩色模式），`02` 亮度 1–100 %，`03` 色温 0–38（2700 K + 每级 100 K），`04` 饱和度 0–100 %，`05` 场景 1–9，`06` 按键（`01` 开，`02` 关，`03` S-，`04` S+，`06` 白光模式）；`zz` 区域：`00` 全部，`01`–`08` |
| 状态查询 | `43 00 00 80 00 00 00 00 00 80 80 C3` | 网关以状态帧 `44` 应答 |
| 状态（网关 → 应用） | `42` / `44` `00 00 00 mm hh tt bb ss 0B dd xx` | `42` 变化报告（最后一次变化约 2.5 秒后），`44` 查询应答；`mm` 模式：`00` 关，`01` 彩色，`02` 白光，`03`–`0B` 场景 1–9；`hh` 色调，`tt` 色温级别，`bb` 亮度，`ss` 饱和度（白光模式下为 0），`dd` DMX 起始地址的低字节。状态中不包含区域 |
| DMX 起始地址 | `49 00 00 0B 02 aa aa 00 00 zz 80 ss` | `aa aa` 地址 1–512（高字节、低字节），`zz` 区域；应答 `49 00 00 0B 02 01 tt bb ss aa aa xx` |

按键 `06 05` 同样会关闭灯（再按一次灯仍保持关闭，它不是开关切换键）；它与 `06 02` 有何不同尚不清楚，适配器不使用它。网关根据这些命令推导出标准数据点 20–23；适配器只使用数据点 20（开/关，比状态更早到达），其余一切都以数据点 101 的状态为准。写入涂鸦颜色数据点 24 不会改变灯的颜色——MiBoxer 应用也不使用它。

用于自行实验的原始访问：`dp101.hex` 接受 11 个字节（会自动追加校验和），例如 `43 00 00 80 00 00 00 00 00 80 80` 查询状态。

## 限制

- 网关为所有灯报告一个状态（最后一次设置），而不是每个区域的状态——见[区域](#区域)。
- 网关不报告场景速度（S+ / S-）。
- 无法看出灯是否真的通过无线电收到了命令：状态来自网关。
- 网关仍会向涂鸦云报告其状态。完全阻止其访问互联网可能会使其不可靠。MiBoxer 应用的定时器需要云，适配器的定时器则不需要。

## 日志与故障排除

适配器按照固定方案记录日志，使日志随时都能用于故障排除：

| 级别 | 记录内容 |
| --- | --- |
| error | 导致适配器无法工作的配置错误（缺少设备 ID、本地密钥不是 16 个字符） |
| warn | 需要您处理的问题——只报告一次，之后在问题解决前仅以 debug 级别记录：网关拒绝连接、数据无法解密（本地密钥错误）、网关未确认命令、状态查询无应答、意外的数据点值或状态帧、设置不完整或缺少位置（用于太阳事件）的定时器、未能切换灯的定时器、网关未确认的 DMX 起始地址 |
| info | 里程碑：启动时的配置摘要、找到网关、已连接、连接丢失、连接恢复稳定、已删除另一种区域方式的对象、启用的定时器数量、定时器已暂停或重新启用 |
| debug | 每一步的输入、决策和耗时：状态变化 → 转换为数据点 101 的帧（并说明额外帧的原因，例如“先开灯”）→ 命令队列 → 发送 → 由状态确认（或仍缺少哪个值），每个接收到的数据点和状态以及更新的状态、状态查询、搜索，每个定时器的计划、下次运行（太阳事件、偏移、随机偏差）和执行。命令（`#12`）和连接尝试（`Attempt #3`）均有编号，因此可以追踪同一条命令的所有日志行 |
| silly | 另外还有 tuyapi 库的协议跟踪（数据包、ping/pong），标记为 `[tuyapi]` |

每条消息都以一个组件标记开头：`[cfg]` 配置，`[conn]` 连接，`[rx]` 网关 → 状态，`[cmd]` 状态 → 命令，`[queue]` 命令队列，`[poll]` 状态刷新和查询，`[disc]` 搜索，`[dp101]` 原始帧，`[timer]` 定时器，`[unload]` 关闭，`[tuyapi]` 库跟踪。本地密钥和会话密钥绝不会出现在日志中——配置摘要只显示密钥的长度。

更改级别：Admin → **实例** → 专家模式 → `miboxer-wl433.0` 的日志级别 → `debug`（协议跟踪用 `silly`；之后重启实例）。报告问题时请附上 debug 日志和 `dp101.history` 的内容。
